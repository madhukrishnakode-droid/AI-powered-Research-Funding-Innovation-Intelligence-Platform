# Radial — Research Intelligence Workspace

A modern React dashboard for researchers to track **trends, patents, funding opportunities, citations, and innovation health** in one place. Radial ships with real Google OAuth 2.0 sign-in and a small local exchange server so credentials stay server-side.

## Features

- **Research intelligence modules** — Dashboard, Patents, Funding recommendations, Publications, Innovation Score, Reports, Collaborations, Lab Resources, Alerts, Settings, and Profile
- **Google sign-in** — OAuth 2.0 Authorization Code + PKCE with a local token-exchange server
- **Demo mode** — falls back to a demo profile when no credentials are configured, so the UI is always explorable
- **Gradient design system** — dark slate gradient shell, light content surfaces, blue→cyan / purple / teal gradients, glow shadows, and subtle hover animations
- **File-based routing** with TanStack Router (type-safe, auto-generated route tree)
- **Responsive layout** with a collapsible sidebar

## Tech Stack

## Getting Started

### Prerequisites

- Node.js 18+ (uses the built-in `fetch` on the server side)

### Install

```bash
npm install
```

### Configure OAuth (optional)

1. **Google** — [Google Cloud Console](https://console.cloud.google.com/apis/credentials) → create an OAuth client ID of type **Web application**. Add `http://localhost:5173/auth/callback` (and optionally `http://127.0.0.1:5173/auth/callback`) to **Authorized redirect URIs**.
2. Copy `.env.example` to `.env` and fill in the values:

```bash
cp .env.example .env
```

> Note: Google requires a **client secret** at the token-exchange step even when using PKCE. Without `GOOGLE_CLIENT_SECRET` set, the redirect succeeds but the final sign-in fails.

### Run

```bash
npm run dev:full
```

This starts both the Vite dev server (port `5173`) and the OAuth exchange server (port `3001`) concurrently. Open **http://localhost:5173** in your browser.

If you only need the UI without sign-in, `npm run dev` works too (demo mode activates automatically).

## Environment Variables

| Variable | Where | Purpose |
| --- | --- | --- |
| `VITE_GOOGLE_CLIENT_ID` | browser | Google OAuth client ID |
| `VITE_OAUTH_EXCHANGE_URL` | browser | Exchange endpoint (defaults to the Vite proxy `/api/oauth/exchange`) |
| `GOOGLE_CLIENT_ID` | server | Server-side Google client ID |
| `GOOGLE_CLIENT_SECRET` | server | **Secret — never commit or expose** |
| `PORT` | server | Exchange server port (default `3001`) |

`.env` is gitignored. Client IDs may be exposed (they're public by design), but client **secrets must never** be placed in `VITE_`-prefixed variables or committed to the repo.

## How OAuth Works

1. The client generates a PKCE verifier/challenge and `state`, stores them in `sessionStorage`, then redirects to the provider.
2. The provider redirects back to `/auth/callback?code=...&state=...`.
3. The client POSTs the code to the local exchange server (`/api/oauth/exchange/google`).
4. The server exchanges the code for a token using the server-side secret and returns a profile (name, email, picture).
5. The profile is persisted to `localStorage` and the session starts.

In development, Vite proxies `/api` → `http://localhost:3001` so the browser only ever talks to one origin.

## Deployment Notes

- **Vercel** — the project is configured for Vercel (`vercel.json` in the repo root, Root Directory `radial`). `vercel.json` rewrites `/api/*` to the serverless function at `api/index.mjs` (the Express exchange server) and falls back to `index.html` for client-side routing.
- **Environment variables** — set these in Vercel (Settings → Environment Variables): `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and `VITE_GOOGLE_CLIENT_ID` (Vite inlines `VITE_` vars at build time, so redeploy after setting them). Do **not** commit secrets to the repo.
- **Google OAuth** — add your production URL to the OAuth client's Authorized redirect URIs, e.g. `https://<your-app>.vercel.app/auth/callback`.
- The dev server (`npm run server` / `npm run dev:full`) still runs the same Express app locally on `:3001`.
- `dist/`, `node_modules/`, `.env`, and log files are gitignored.
